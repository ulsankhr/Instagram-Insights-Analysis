# Instagram Insight Analysis

**Python과 Selenium을 활용하여 인스타그램 게시물의 업로드 요일·시간대에 따른 좋아요 및 도달 성과를 분석하고, 성과가 높은 게시 시간대를 도출한 데이터 분석 프로젝트**

<br>

## 1. 프로젝트 소개

### 📌 프로젝트 배경

인스타그램 게시물을 운영하면서 **"게시물을 언제 업로드해야 더 많은 사람에게 도달하고, 더 많은 좋아요를 받을 수 있을까?"**&#xB77C;는 질문에서 프로젝트를 시작했습니다.

단순히 게시물별 성과를 비교하는 것이 아니라,

* 어떤 **요일**에 게시했을 때 반응이 높은지
* 어떤 **시간대**에 게시했을 때 반응이 높은지
* 특정 **요일 × 시간대 조합**에서 성과가 높은지
* 사전에 예상한 결과와 실제 데이터 분석 결과가 일치하는지

를 확인하고자 했습니다.

이를 위해 인스타그램 게시물 데이터를 직접 수집하고, Python을 활용하여 데이터 전처리 및 탐색적 데이터 분석(EDA)을 수행했습니다.

---

## 2. 프로젝트 목표

### 🎯 핵심 질문

> **"인스타그램 게시물의 업로드 요일과 시간대에 따라 좋아요와 도달 성과에 차이가 발생하는가?"**

이를 바탕으로 다음과 같은 세부 분석 질문을 설정했습니다.

### Q1. 요일에 따라 게시물 성과가 달라지는가?

요일별 평균 좋아요 수와 평균 도달 수를 비교하여 성과가 높은 요일을 확인했습니다.

### Q2. 시간대에 따라 게시물 성과가 달라지는가?

하루를 3시간 단위로 구간화하여 시간대별 평균 좋아요 수와 평균 도달 수를 비교했습니다.

### Q3. 특정 요일과 시간대의 조합에서 성과가 높은가?

요일과 시간대를 동시에 고려하여 **요일 × 시간대별 평균 좋아요 및 도달 수**를 분석했습니다.

## 5.2 Selenium을 활용한 웹 크롤링

인스타그램 게시물의 업로드 날짜 및 시간을 수집하기 위해 **Selenium**을 사용했습니다.

단순히 기존 CSV/Excel 데이터를 사용하는 대신, 실제 웹 페이지에서 필요한 데이터를 수집하는 과정을 경험하는 것을 프로젝트의 주요 목표 중 하나로 설정했습니다.

### 데이터 수집 과정

1. Selenium WebDriver 실행
2. 인스타그램 로그인
3. 개인 프로필 페이지 접근
4. 페이지를 끝까지 스크롤하여 게시물 로드
5. 게시물 URL 추출
6. 각각의 게시물 페이지 접근
7. HTML의 `<time>` 태그에서 업로드 날짜·시간 추출
8. 수집 결과를 DataFrame으로 변환
9. Excel 파일로 저장

```python
# 게시물 링크 추출
posts = driver.find_elements(By.XPATH, "//a[contains(@href, '/p/')]")

post_links = [
    post.get_attribute('href')
    for post in posts
]

print(f"Found {len(post_links)} posts.")
```

게시물별 페이지에 접근한 후 `<time>` 태그의 `datetime` 속성을 추출했습니다.

```python
date_time = driver.find_element(
    By.TAG_NAME,
    'time'
).get_attribute('datetime')

dates.append(date_time)
```

이를 통해 게시물의 업로드 날짜와 시간을 수집했습니다.

# 6. 데이터 수집 과정에서 발생한 문제

데이터 수집 과정에서 인스타그램의 시간대 데이터를 크롤링하던 중 **자동화된 활동으로 의심되는 경고가 발생**했습니다.

이에 따라 좋아요 수와 도달 수까지 자동으로 수집하는 방식은 안정적으로 진행하기 어렵다고 판단했습니다.

```text

→ 수동 수집

도달 수
→ 수동 수집
```

이처럼 실제 데이터 수집 과정에서 발생한 문제에 대응하여 **자동 수집 가능한 데이터와 수동 수집이 필요한 데이터를 구분**하여 프로젝트를 진행했습니다.

크롤링한 날짜·시간 데이터를 Pandas의 datetime 형식으로 변환했습니다.

insight['날짜_시간'] = pd.to_datetime(

## 8.2 시간대 보정

이 과정을 통해 시간 데이터를 한국 시간 기준으로 보정한 후 분석에 활용했습니다.

## 8.3 요일 변수 생성

날짜 데이터에서 요일을 추출하고, 분석 및 시각화를 위해 영어 요일을 한글 요일로 변환했습니다.

```python
weekday_map = {
    'Monday': '월요일',
    'Tuesday': '화요일',
    'Wednesday': '수요일',
    'Thursday': '목요일',
    'Friday': '금요일',
    'Saturday': '토요일',
    'Sunday': '일요일'
}

insight['요일'] = (
    insight['날짜']
    .dt.day_name()
    .map(weekday_map)
)
```

또한 요일 순서를 월요일부터 일요일까지 고정하여 시각화 시 자연스러운 순서로 표시되도록 처리했습니다.

```python
day_order = [
    '월요일', '화요일', '수요일',
    '목요일', '금요일', '토요일', '일요일'
]

insight['요일'] = pd.Categorical(
    insight['요일'],
    categories=day_order,
    ordered=True
)
```

# 9. 결측치 처리

분석 과정에서 일부 게시물의 **도달 수 데이터가 결측치(NaN)**&#xB85C; 존재했습니다.

해당 데이터에 대해 평균값을 계산하고 결측치를 평균값으로 대체했습니다.

```python
average_reach = insight['도달'].mean()

insight['도달'] = insight['도달'].fillna(
    average_reach
)
```

### 결측치 처리 방식

```text
도달 데이터 확인
      ↓
결측치 존재
      ↓
전체 평균 도달 수 계산
      ↓
결측값을 평균값으로 대체
```

> ※ 본 프로젝트에서는 분석을 진행하기 위해 평균 대체법을 적용했습니다.
> 향후 분석에서는 결측치가 발생한 원인을 구분하고, 결측치를 제외한 분석 결과와 평균 대체 결과를 비교하는 방식으로 데이터 처리의 영향을 검증할 수 있습니다.

# 10. 시간대 구간화

게시물 업로드 시간을 그대로 사용하면 시간별 데이터가 지나치게 세분화될 수 있기 때문에 **3시간 단위로 시간대를 구간화**했습니다.

```python
insight['시간대'] = insight['시간'].apply(
    lambda x:
    f"{(x.hour // 3) * 3:02d}:00-"
    f"{((x.hour // 3) * 3 + 3):02d}:00"
)
```

예를 들어,

```text
00:00 ~ 03:00
03:00 ~ 06:00
06:00 ~ 09:00
09:00 ~ 12:00
12:00 ~ 15:00
15:00 ~ 18:00
18:00 ~ 21:00
21:00 ~ 24:00
```

와 같이 3시간 단위로 그룹화했습니다.

이를 통해 **게시 시간대별 평균 좋아요와 평균 도달 수**를 비교했습니다.

# 15. 요일 × 시간대 분석

요일과 시간대를 동시에 고려하기 위해 Pivot 형태의 데이터를 생성했습니다.

```python
likes_by_day_time = (
    insight
    .groupby(['요일', '시간대'])['좋아요']
    .mean()
    .unstack()
)

reach_by_day_time = (
    insight
    .groupby(['요일', '시간대'])['도달']
    .mean()
    .unstack()
)
```

단순한 요일별 또는 시간대별 분석만으로는 특정 조합의 성과를 확인하기 어렵기 때문에 **Heatmap을 활용하여 요일 × 시간대별 성과를 비교**했습니다.

### 🎯 가장 중요한 발견

**게시 요일만 보는 것보다 요일과 시간대를 함께 분석했을 때 보다 구체적인 게시 전략을 도출할 수 있었습니다.**

분석 결과,

```text
요일별 분석
↓
일요일 좋아요 성과 높음

시간대별 분석
↓
21:00~03:00 성과 높음

요일 × 시간대 분석

높은 도달 성과 확인
```

따라서 향후 게시물 운영 시 해당 시간대를 **우선적인 테스트 시간대**로 설정하고 추가 데이터를 확보하여 성과를 비교할 수 있습니다.

# 21. 프로젝트를 통해 배운 점

## 1️⃣ 실제 데이터 수집 경험

Selenium을 활용하여 웹 페이지에서 직접 데이터를 수집하면서 **웹 데이터의 구조를 파악하고 필요한 정보를 추출하는 과정**을 경험했습니다.

특히 단순한 데이터 분석뿐만 아니라 데이터 확보 단계에서 발생할 수 있는 문제까지 직접 경험했습니다.

---

## 2️⃣ 데이터 품질 문제 대응

크롤링 과정에서 자동화 활동 경고가 발생하면서 모든 데이터를 동일한 방식으로 수집하기 어려웠습니다.

이에 따라 데이터를 무리하게 자동 수집하기보다 **수집 가능한 데이터는 자동화하고, 제한이 발생한 데이터는 수동 수집하는 방식으로 데이터 확보 전략을 변경**했습니다.

---

## 3️⃣ 전처리의 중요성

단순히 데이터를 분석하는 것이 아니라,

* 날짜 및 시간 형식 변환
* 시간대 보정
* 요일 파생변수 생성
* 시간대 구간화
* 결측값 처리
* 데이터 병합

등의 과정을 거쳐야 실제 분석이 가능한 형태의 데이터셋을 만들 수 있음을 경험했습니다.

---

## 4️⃣ 가설보다 데이터가 중요하다는 점

분석 전 예상했던 결과와 실제 분석 결과가 달랐습니다.

이를 통해 데이터 분석에서는 자신의 예상에 결과를 맞추기보다,

> **가설을 세우고 → 데이터를 통해 검증하고 → 결과에 따라 해석하는 과정**

이 중요하다는 것을 경험했습니다.

# 22. 한계점 및 향후 개선 방향

본 프로젝트는 개인 인스타그램 데이터를 활용한 미니 프로젝트이기 때문에 분석 결과를 일반적인 인스타그램 사용자 전체에 적용하기에는 한계가 있습니다.

### 한계점

#### ① 분석 데이터의 범위

개인 계정의 게시물 데이터를 기반으로 분석했기 때문에 표본의 범위가 제한적입니다.

#### ② 평균값 중심의 분석

요일 및 시간대별 평균값을 사용했기 때문에 개별 게시물의 특성에 따른 차이를 충분히 설명하기 어렵습니다.

#### ③ 결측치 처리

도달 수 결측치를 평균값으로 대체했기 때문에 해당 처리 방식이 분석 결과에 영향을 줄 가능성이 있습니다.

#### ④ 인과관계 판단의 어려움

특정 시간대에 게시했기 때문에 좋아요와 도달이 증가했다고 단정할 수는 없습니다.

게시물의 콘텐츠, 주제, 이미지, 해시태그 등 다른 요인이 성과에 영향을 미쳤을 가능성이 있습니다.

추가 데이터가 확보된다면 다음과 같은 분석을 진행할 수 있습니다.

더 많은 기간의 데이터를 확보하여 특정 시간대의 높은 성과가 **일시적인 현상인지 반복적으로 나타나는 패턴인지** 확인할 수 있습니다.

### 4. 통계적 검증

단순 평균 비교를 넘어 통계적 검정을 활용하여 요일 및 시간대별 성과 차이가 통계적으로 유의미한지 검증할 수 있습니다.

## Selenium을 활용한 게시물 날짜·시간 수집

```python
posts = driver.find_elements(
    By.XPATH,
    "//a[contains(@href, '/p/')]"
)

post_links = [
    post.get_attribute('href')
    for post in posts
]

for link in post_links:
    driver.get(link)
    time.sleep(5)

    try:
        date_time = driver.find_element(
            By.TAG_NAME,
            'time'
        ).get_attribute('datetime')

        dates.append(date_time)

    except Exception as e:
        print(
            f"Error extracting date from {link}: {e}"
        )
```
